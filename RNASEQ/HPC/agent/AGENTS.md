# AGENTS.md — RNA-seq project (Rephill Lab)

This directory is **one lab member's RNA-seq project**, run with the lab's shared Nextflow pipeline at
`/project/rephilllab/RNASEQ`. You are here to help this user run the pipeline on *their* data, check results, and customize
*their* analysis. You are not here to change the pipeline itself.

The pipeline counts reads per gene for each library (HISAT2 alignment, Picard duplicate marking, featureCounts) and merges the
counts into one table. It can also run a DESeq2 **differential expression** analysis on that table (`run_deg: true`, off by default;
see "Differential expression" below). Without it, differential expression comes later, from the table in `results/counts/`.

## Hard rules

1. **Never edit anything under `/project/rephilllab/`** (`RNASEQ/`, `bin/`, `nf_containers/`) unless the user explicitly asks
   to change the **lab-wide** pipeline. Every lab member runs those files. To change how this project's analysis works, use a
   per-project override (see "Customizing"), never an edit to the shared copy.
2. **Only launch the pipeline with `run_rnaseq.sh`.** Do not call `nextflow`, `hisat2`, `samtools`, `featureCounts`, `Rscript`
   or `python` analysis scripts yourself, and do not `bsub` your own jobs. `run_rnaseq.sh` handles LSF submission, containers,
   logging and `-resume`.
3. **Do not run anything compute- or memory-heavy in the terminal.** The login node caps memory at about 2 GB. Reading logs,
   CSVs and small files is fine; opening a BAM with anything heavier than `samtools view -H`, or running an analysis script, is not.
4. **Raw FASTQs and BAMs are the only copy.** If `fastq_dir` is set in `config.yaml`, the first run *moves* (not copies) that
   directory's FASTQs into `original_data/fastq/` and rewrites `fastq_dir`; do not change it back. Otherwise the paths in
   `samplesheet.csv` are used exactly as given and nothing is moved. Never delete, move or overwrite raw data.
5. **Ask before destructive or expensive actions:** deleting `results/`, `intermediate_files/`, `metadata/`, `.nextflow/`, or the
   Nextflow work directory (`/project/rephilllab/nf_work/$USER/<this directory's name>/`), or launching a run when nothing has
   changed. A full run aligns every library and is expensive.
6. **Do not hand-edit files in `results/` or `intermediate_files/`.** They are regenerated by the pipeline; change the inputs or
   an override instead.
7. **Do not guess data paths.** FASTQ, BAM, HISAT2 index and GTF paths come from the user. Ask.
8. **Never change `strandedness` on your own.** The strandedness check reports what the libraries look like; it never changes
   the counts. Whether the configured value is right is the user's decision (see "Strandedness" below).

## Layout

```
config.yaml                    the run's settings: the file you usually edit (keys: README.md, "config.yaml keys")
samplesheet.csv                one row per library (schema below)
utils/                         this project's replacements for pipeline scripts (see "Customizing"); created by init, empty until used
original_data/fastq/           FASTQs, only if fastq_dir mode is used
intermediate_files/            trimmed FASTQs (trimmed/), FASTQs made from BAMs (fastq_from_bam/), aligned and filtered BAMs
results/                       all outputs (see "Results")
metadata/nf_logs/              LSF logs of each run's head job (read these first)
metadata/.nextflow.log         Nextflow's detailed log (the run's first ERROR is the cause)
metadata/pipeline_info/        execution trace, report, timeline and DAG; the file names carry the launch timestamp
.nextflow/                     Nextflow's resume cache: leave alone
examples/                      starter files: the config.yaml template, the samplesheet template, examples/projects/
```

This directory is a git repository tracking `config.yaml`, `samplesheet.csv`, `examples/` and any override scripts. Data,
results and logs are gitignored. Committing after a meaningful config change is a good habit, but ask the user first.

## How to run

```bash
run_rnaseq.sh init         # once, in a new empty project directory: scaffolds files, git init, never runs anything
# edit samplesheet.csv and config.yaml (project_name, hisat2_index, gtf, strandedness)
run_rnaseq.sh              # from this directory; reads ./config.yaml (or: run_rnaseq.sh other.yaml)
```

It is safe to run from the login node: it stages `fastq_dir` if set, makes sure the Nextflow launcher exists, and submits one LSF
head job (queue rhel9, 8 GB, 168 h) and returns. The head job runs every step as its own LSF job, each in a container. Startup
validation of `config.yaml` and `samplesheet.csv` happens first and fails with a clear message before any job is submitted.

Re-running is always `run_rnaseq.sh` again. `-resume` is built in, so any step whose inputs, script and settings have not changed
is reused from cache. There is no "run just step X" command: change the thing, re-run, and caching does the rest.

If `run_rnaseq.sh` is not found, the user's `PATH` is missing `/project/rephilllab/bin`, or the symlink has not been created yet.
Tell them; do not edit their `~/.bashrc` without asking.

## Input files

### samplesheet.csv: one row per library

```
sample_id,fastq_1,fastq_2,bam,exclude,<any metadata columns>
```

| Column | Meaning |
|---|---|
| `sample_id` | Unique library name, used verbatim in file names; must match `^[A-Za-z0-9._-]+$`. Not `.R1`: the sample id has no read suffix. |
| `fastq_1`, `fastq_2` | Absolute paths of the R1 and R2 FASTQ (paired-end only). Both are required together. |
| `bam` | Absolute path of a BAM. It is converted back to paired FASTQ first (BAM_TO_FASTQ: `samtools collate`, then `samtools fastq`), and the FASTQs then go through the normal steps. Give either a FASTQ pair or a BAM for each row, not both. |
| `exclude` | `true` drops the row from the whole run; blank or `false` keeps it. Excluded rows stay in the file for the record. |
| other columns | Free metadata (for example `condition`, `sgRNA`, `treatment`). They are checked only for duplicate headers and are copied into `results/samplesheet.tsv` for later differential expression. |

Rules enforced at startup (the run stops with a message): `sample_id` is present and unique and matches the pattern; each row has
either a FASTQ pair or a BAM (not both, not neither); both FASTQ files of a pair are given; every listed file exists; no duplicate
column header; at least one row is not excluded.

### config.yaml keys

The flat `key: value` file. Every key has a default in the pipeline's `nextflow.config`; the reference table is in the README
("Parameters"). The keys with no default are `hisat2_index` (HISAT2 index PREFIX, required) and `gtf` (required). An unknown key
stops the run at startup and the message names it.

## Monitoring a run

```bash
bjobs -u $USER                                          # the head job is rnaseq_<project_name>_<timestamp>
tail -n 50 metadata/nf_logs/nextflow_<timestamp>.out    # latest = ls -t metadata/nf_logs/*.out | head -1
ls -t metadata/pipeline_info/ | head                    # the trace, report and timeline of the latest launch (names carry the timestamp)
```

A run ends with `Pipeline completed successfully` or `Pipeline FAILED` in the `.out` log. Poll every few minutes; alignment of a
full project takes hours.

## When a run fails

1. Read the end of the newest `metadata/nf_logs/nextflow_<timestamp>.out`. It names the failed step, its exit status, the command,
   and its `Work dir:`. For a startup error there is no work dir: the message says what to fix.
2. In that work dir read `.command.sh` (what ran), `.command.err` and `.command.log`. For a step that *succeeded*, the same command
   is saved permanently in that step's `log/` folder under `results/` or `intermediate_files/` (named `<sample>_<step>_command.sh`).
3. Common cases:
   - **Exit status 3** is a known data problem; it is not retried and the message says what to fix. Typical: a HISAT2 run that
     produced an empty BAM (ALIGN); a BAM with no read pairs (BAM_TO_FASTQ); no contig left after `remove_chroms` (BAM_FILTER);
     a strandedness output without the fraction lines (INFER_STRANDEDNESS); an empty per-sample count table (FEATURECOUNTS);
     a gene column that differs between samples (COUNTS_MERGE).
   - **Exit status 137, 140, 143** (out of memory or wall time): retried automatically with more memory. If a step still fails,
     report it to the user.
   - **Run hangs with a task SUBMITTED but no LSF job** (`bjobs -u $USER` shows nothing for it, its work dir has no
     `.command.begin`): the LSF job was aborted at dispatch. The head job's watchdog prints an `RNASEQ WATCHDOG:` block and stops
     the run. Read the block, then relaunch with `run_rnaseq.sh` (finished steps are reused). If it happens again, report it.
   - **Join mismatch messages at the end of `.nextflow.log`** are usually a side effect of an earlier abort: read the first ERROR.
4. Fix the input or config, then re-run `run_rnaseq.sh`. Completed steps are reused.
5. If the failure looks like a bug in the shared pipeline rather than in this project's data or config, **tell the user and stop**.
   Do not patch `/project/rephilllab/RNASEQ`.

## Differential expression (run_deg)

`run_deg: true` adds the DEG steps after the counts. Needed: `deg_comparisons` (CSV: `model`, `design`, `comparison` and one contrast per row:
`factor`+`numerator`+`denominator`, or `coef`, or `add`[+`subtract`]) and sample metadata with the design columns (`deg_metadata`, or the
samplesheet's own columns). Optional: `deg_heatmaps`, `deg_colors`, `deg_label_rules` (CSVs), `deg_reference_levels`
(`treatment=LUC_DMSO,drug=DMSO`), and the `deg_*` parameters in the README ("Differential expression"; the template is `examples/config.yaml`).
To run only the DEG steps on an existing counts table set `deg_counts` as well: no reads, references, QC or MultiQC are needed.
Results are in `results/deg/` (`prepared/`, `qc/`, `<model>/<comparison>/results_<comparison>.csv`, volcano plots, heatmaps, `gene_plots/`).
Choosing the comparisons, the design, `deg_alpha`, `deg_lfc` or the shrinkage is a scientific decision: tell the user and ask. Exit status 3
of a DEG step is a data problem (an unknown factor level, a design that is not full rank, a count column without metadata); the message
says what to fix. The DEG steps run in the image `/project/rephilllab/nf_containers/omics-r_1.0.sif`: if they fail to start on the cluster, tell the user the lab image
may not exist yet.

An interaction model, or any other custom statistical test, is not part of the pipeline: it goes in a custom script in the project's `utils/`
folder. Such a script can read `results/deg/prepared/counts_edited.rds` and `sample_metadata_edited.rds`; on the Docker versions it is run with
`run_rnaseq script utils/X.R`. Do not write it unless the user asks, and the choice of model is theirs.

## Strandedness

`strandedness` (unstranded, forward or reverse) sets how featureCounts counts: unstranded `-s 0`, forward `-s 1`, reverse `-s 2`.
The default `unstranded` is the legacy GG setting. The automatic check (RSeQC `infer_experiment.py` on a sample of reads per BAM)
writes `results/qc/strandedness/strandedness.tsv` with the fraction of reads explained by each strand orientation, the call
(forward, reverse or unstranded, by `strand_call_threshold`), and a `mismatch` column (true when the call differs from the
configured value). A mismatch prints a `WARN` at the end of the run and nothing else happens: the counts are not changed.

When the check reports a mismatch, tell the user the numbers from that table and ask which library prep was used. Changing
`strandedness` is their decision; re-running after the change re-counts every library (featureCounts is re-run, alignment is not).

## Customizing this project's analysis

Every step runs one script from `/project/rephilllab/RNASEQ/bin/`. To change a step for this project only, copy the script into
`utils/`, edit the copy, and add a `config.yaml` line **named after the script** (file name without extension) with the copy's path:

```bash
cp /project/rephilllab/RNASEQ/bin/featurecounts.sh utils/   # 1. copy
# 2. edit utils/featurecounts.sh (keep its header's CLI and output contract)
# 3. add to config.yaml:   featurecounts: utils/featurecounts.sh
run_rnaseq.sh                                                 # 4. only that step (and what depends on it) re-runs
```

Add `<script name>_args: "..."` to pass extra arguments to a shipped script. Each script's header lists the arguments the pipeline
passes and the files it must write; keep both compatible. `.py` runs with `python3`, `.R` with `Rscript`, anything else with `bash`.

Scripts (= the `config.yaml` key that replaces each): `bam_to_fastq.sh`, `fastqc.sh`, `trim.sh`, `align.sh`, `alignment_summary.py`,
`bam_filter.sh`, `mark_duplicates.sh`, `gtf_to_genepred.sh`, `genepred_to_bed12.sh`, `infer_strandedness.sh`,
`qc_strandedness_table.py`, `featurecounts.sh`, `counts_merge.py`, `samplesheet_tsv.py`, `multiqc.sh`, and for the DEG steps
`deg_common.R` (helpers), `deg_prepare.R`, `deg_qc.R`, `deg_deseq2.R`, `deg_results.R`, `deg_transform.R`, `deg_volcano.R`, `deg_heatmap.R`,
`deg_ma.R`, `deg_gene_plot.R`.

Some keys are both a switch and a script name: `trim` (`true`/`false` switch) and `mark_duplicates` (switch). A value that is a
string (a path) is read as a replacement script; `true` or `false` is read as the switch. Do not add a script whose name equals a
parameter name.

Anything that changes the counting method (the featureCounts options, the duplicate policy, the MAPQ filter, the strandedness) is a
scientific decision: tell the user and get confirmation first.

## Results

```
results/counts/<project_name>_counts.txt          the merged counts table: Gene + one column per sample (sample ids, no .R1)
results/counts/gene_length.txt                    gene length and strand from the first sample's featureCounts table
results/counts/featurecounts_summary.tsv          featureCounts assignment status per sample
results/counts/per_sample/                        per sample: S_counts.txt, S_featurecounts.txt, S_featurecounts.txt.summary
results/bam/final/                                the BAM that was counted (S.final.bam and .bai)
results/qc/fastqc/raw/, results/qc/fastqc/trimmed/   FastQC reports, both mates
results/qc/trimmomatic/                           Trimmomatic logs
results/qc/hisat2/                                HISAT2 summaries and alignment_summary.tsv (warning threshold flags)
results/qc/samtools/                              raw and filtered flagstat and idxstats
results/qc/picard/                                Picard duplicate metrics
results/qc/strandedness/                          infer_experiment output per sample, strandedness.tsv, genes.bed12
results/qc/multiqc/                               multiqc_report.html: start here for an overview
results/samplesheet.tsv                           the non-excluded samplesheet rows, with the metadata columns
results/deg/                                      differential expression (only with run_deg: true): prepared/, qc/, <model>/, gene_plots/
intermediate_files/                               trimmed FASTQs, FASTQs made from BAMs, aligned and filtered BAMs
```

When summarising results, start from `results/qc/multiqc/multiqc_report.html`, then `results/qc/strandedness/strandedness.tsv`
(the `mismatch` column) and `results/qc/hisat2/alignment_summary.tsv` (the warning flags) before interpreting the counts.

Duplicates are marked, not removed (default), and featureCounts counts every read in the marked BAM, duplicates included. That is
the legacy behaviour and a deliberate choice of the user; say so if you summarise the counts.
