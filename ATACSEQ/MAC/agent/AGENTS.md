# AGENTS.md — ATAC-seq project (Rephill Lab), Docker version for Mac

This folder is **one lab member's ATAC-seq project**, run with the lab's shared pipeline (Docker version for Mac)
installed on this computer at:

    {{PIPELINE_DIR}}

You are here to help this user run the pipeline on *their* data, check results, and customize *their* analysis. The user
is usually a wet-lab scientist: do the technical work, explain in plain language, and ask them for what only they know.
You are not here to change the pipeline itself.

## Hard rules

1. **Never edit anything in the pipeline folder above** (or anywhere in its git clone) unless the user explicitly asks to
   change the **lab-wide** pipeline. To change how this project's analysis or plots work, use a per-project override (see
   "Customizing").
2. **Only launch the pipeline with this project's `bash utils/run_atacseq.sh run`, and run this project's own analysis scripts
   with its `script` command** (see "Analyses beyond the pipeline"). Don't call `docker run`, `nextflow`, `bowtie2`,
   `samtools`, `sambamba`, `bedtools`, `macs3`, `trimmomatic`, `Rscript`, `python`, or the pipeline's `bin/` scripts yourself.
   The launcher handles Docker, the input checks, logging and resuming. Never call `RUN_ANALYSIS.command` (it's the
   double-click launcher for humans and waits for Enter at the end).
3. **Don't run analysis work on the computer itself.** Reading logs, CSVs and other small text files is fine. Opening FASTQ or
   BAM files, or running any analysis, is not: that goes through `script` (or `run`), where the pipeline's image and memory
   limits apply.
4. **The raw FASTQs are the user's data.** They stay where the user keeps them: the paths in `samplesheet.csv` point to them,
   and the launcher reads them in place, read-only. Never move, copy, rename, delete or overwrite them. A library may instead
   give a final BAM (the samplesheet `bam` column), read in place in the same way; there is no FASTQ folder mode in this
   version: leave `fastq_dir` `null`.
5. **Ask before destructive or expensive actions:** deleting `results/`, `intermediate_files/` or `metadata/`; `clean` (it
   deletes `metadata/work/` and `metadata/.nextflow/`); changing `keep_work`; or launching a run when nothing has changed. A full
   run takes hours and a lot of disk.
6. **Don't hand-edit files in `results/` or `intermediate_files/`.** They are regenerated by the pipeline; change the inputs or
   an override instead.
7. **Don't guess data paths.** FASTQ, genome index, blacklist, GTF and TSS paths come from the user. Ask.
8. **Never assume the experiment.** Ask the user for the biological and technical context, and flag (never silently resolve)
   data that contradict it; see the next section. Record the answers in `CONTEXT.md`.
9. **The computer's settings are the user's.** Don't change Docker Desktop's settings (its Memory limit included), and don't
   install software (Docker Desktop, Homebrew packages, Rosetta, or anything inside the container at run time) without asking.
   When the launcher asks about installing Docker Desktop or Rosetta 2, answer only with the user's OK; don't add `--yes` on your own.

## Ask about the experiment; never assume it

You know the pipeline; only the user knows the experiment. Before you prepare inputs, choose groups, interpret results, or
write Methods or figure text, ask the user for the context below, unless they already gave it in this conversation or it is in
`CONTEXT.md`. Ask even when it seems obvious.

- **The assay:** ATAC-seq, the kit or protocol, the transposase preparation and the input amount; the sequencing (paired-end
  read length, which run(s) and lanes). This pipeline version supports paired-end data only; say so if the data are
  single-end.
- **The biology:** cell type or model, the treatments, doses and timepoints, the genotype.
- **Each library:** which libraries are biological replicates and which are technical; which libraries are normalised together
  (`tmm_group`) and which are pooled for one peak call (`peak_group`); and anything that went wrong (low input, a failed
  library, a re-sequenced library).
- **The question:** which regions should open or close, and the expected positive and negative loci (genes or regions that
  should or should not change in accessibility).
- **The normalisation and the peaks:** whether a global change in accessibility is expected (TMM assumes most regions do not
  change); whether peaks should be called per group (as configured) or merged (`peak_merges.csv`); the expected peak width (narrow
  is the default).
- **The Tn5 shift:** whether to apply the Tn5 offset correction (`tn5_shift`, off by default), and why.
- **Only if the downstream analyses are wanted:** the comparisons (which values of which samplesheet column form the case and
  the control, which column is a block such as a cell line, which peak groups each side uses, which lines are pooled), the fixed
  dispersion of a comparison without replicates, the motif targets and the thresholds. Ask for each one; never choose them.

- Ask in short batches (3-6 questions at a time), in plain language, and say why each answer matters. Keep asking until the
  answers are specific; "the usual" or "like last time" is not an answer, so ask what it was.
- **Never infer the design from names** (`rep2`, `A`/`B`, `ctrl`, `T0`, `T14`, `WT`, `KO`, `hi`/`lo`, `high`/`low`) or from what
  is "typical" for ATAC-seq. Ask what each name means.
- Use only what the user confirmed. Where an answer is missing, say what you would do instead and wait for an explicit OK; never
  fill the gap silently, and never pick the replicates, groups or comparisons yourself.
- **Write the answers down** in `CONTEXT.md` in the project folder (dated, in the user's words, with open questions marked as
  open). Read it at the start of every session; ask the user to confirm it is still right before you rely on it, and add to it
  as you learn more. It is tracked by git with the inputs.
- **When the data seem to contradict the context, flag it; don't reinterpret.** Examples: a low TSS enrichment
  (`results/qc/tss_enrichment/`); a high chrM fraction (`results/qc/chrom_fraction/`); a fragment-size distribution without the
  expected nucleosome pattern (`results/qc/fragment_sizes/`); a replicate that differs strongly from its partner; a "global loss"
  treatment where the TMM factors do not move (`results/scale_factors/`); a library with a low alignment rate
  (`results/qc/alignment/`). Show the user the numbers and the file they come from, say what the data would be consistent with,
  and ask. The user's description stands until they change it; don't rename samples, drop them or change groups on your own.
- Subagents cannot talk to the user: put the confirmed context (or the path to `CONTEXT.md`) in every brief, and pass their
  "Questions for the user" back to the user rather than answering them yourself.

## Running

From this folder (Terminal):

```bash
bash utils/run_atacseq.sh run --detach    # start (or resume) the analysis; returns immediately
bash utils/run_atacseq.sh status          # running / succeeded / failed + the last log lines
bash utils/run_atacseq.sh logs            # follow the live log (Ctrl+C stops watching; the run goes on)
bash utils/run_atacseq.sh stop            # stop; the next run resumes
bash utils/run_atacseq.sh clean           # delete metadata/work and the resume cache and the work volume (asks first)
```

A different config file: `run --detach other.yaml`.

The analysis runs inside Docker Desktop, in the background: closing the terminal doesn't stop it, but the Mac must stay on,
plugged in, lid open (the launcher prevents idle sleep while the run is active). Docker Desktop must be running; the launcher
starts it if needed (it can take a minute or two).

Re-running is always `bash utils/run_atacseq.sh run` again. Resuming is built in, so any step whose inputs, script and settings
haven't changed is reused. Only what changed, and anything downstream of it, re-runs. There is no "run just step X" command:
change the thing, re-run, and caching does the rest.

Nextflow's work folder and resume cache are kept by default (`keep_work: true`): with `work_volume: true` (the default) they
are in the project's Docker volume on Docker Desktop's disk; with `work_volume: false` they are `metadata/work/` and
`metadata/.nextflow/`. A re-run then resumes. With `keep_work: false` they are deleted after a successful run, and re-running
recomputes everything. Failed or stopped runs always keep them. `publish_mode` defaults to `auto`: files in `results/` are copies
or hard links of the work files, so big files are not stored twice. Never edit a published file in place (replacing or deleting
is fine). An explicit `publish_mode` in `config.yaml` wins.

First time on a Mac: Docker Desktop and the pipeline's software image are a one-time setup. Ask the user first, then run
`bash "{{PIPELINE_DIR}}/run_atacseq.sh" setup --yes` (it installs Docker Desktop with Homebrew if Homebrew is present, after
asking; without Homebrew it prints the download page; it installs Rosetta 2 on Apple chips, after asking; it downloads the
image; a restart may be needed). `setup` also prints the versions of the image's tools. Then, in a new project:
`bash "{{PIPELINE_DIR}}/run_atacseq.sh" init "<folder>"`. `init` creates the folder layout, fetches the templates, these agent
files and the `.claude/agents/` kit (when the pipeline has them), writes `.gitattributes`, sets up git if it is installed, and
rewrites the two launchers. It never overwrites `config.yaml`, the CSVs or the agent files.

If `utils/run_atacseq.sh` here fails with "No such file or directory", the pipeline folder moved: re-run
`bash "<new pipeline folder>/run_atacseq.sh" init "<this folder>"`.

## Input files

### samplesheet.csv: one row per library

```
sample_id,fastq_1,fastq_2,condition,replicate,tmm_group,tmm_group_legacy,peak_group,exclude,bam
```

| Column | Meaning |
|---|---|
| `sample_id` | Unique library name. Used verbatim in file names; must match `^[A-Za-z0-9][A-Za-z0-9_.-]*$`. |
| `fastq_1`, `fastq_2` | Paths of the R1 / R2 FASTQ (paired-end only), e.g. `/Volumes/SeqDrive/data/sample_A1_R1.fastq.gz`. Both are required on every row that has no `bam`; on a `bam` row both are empty. |
| `condition`, `replicate` | Labels for the QC tables only (not used by any normalisation). Blank is allowed. |
| `tmm_group` | TMM normalisation group (exact name, used by `tmm_group_column: tmm_group`). Blank = the library is not normalised: no bigWig, no TSS enrichment. A group needs at least 2 active libraries. |
| `tmm_group_legacy` | Second group column, used when `tmm_group_column: tmm_group_legacy` (reproduces the legacy file-name membership). |
| `peak_group` | MACS3 peak group (replicates are pooled, no control). Blank = the library is in no peak calling and gets no FRiP. A `peak_merges.csv` row can name peak groups. |
| `exclude` | empty / `false` / `0` / `no` keep the row; `true` / `1` / `yes` drop it from the whole run (anything else is a startup error). |
| `bam` | Optional. A final BAM of the library instead of FASTQ (the file ends in `.bam` and exists; `fastq_1` and `fastq_2` must be empty). The BAM is assumed filtered, duplicate-removed and blacklist-filtered, and is handled by BAM_PREALIGNED. Each active row has FASTQ or a BAM, not both. |

Rules enforced at startup (the run stops with a message before any step starts): no unknown column (the allowed names are the
table above); `tmm_group_column` names a column of the sheet; unique `sample_id`; every FASTQ exists; no two FASTQ files share a
file name; a TMM group with only one active library is an error (it needs at least 2); a `bam` that is not a `.bam` file or is
missing, and a row with both FASTQ and a BAM. Rows with `exclude: true` are kept in the
file for the record. A group that only has excluded members is not in the run.

### peak_merges.csv: one row per merged peak set (optional)

```
name,peak_groups
merged_peaks,"peak_1,peak_2"
```

`name` is the output name (`results/peaks/merged/<name>.merged.bed`). `peak_groups` is a quoted comma list of `peak_group`
values; each must have an active sample. Set `peak_merges: peak_merges.csv` in `config.yaml` (or `null`). It needs `run_macs3`.

### Downstream CSVs (optional; used only when run_differential, run_annotation or run_motifs is on)

`comparisons.csv`: `name,case,control,group_column,block_column,case_peaks,control_peaks,pooled,fixed_dispersion`. `case` and
`control` are quoted comma lists of values of `group_column` (default `condition`); `block_column` is an optional covariate column
(the legacy gd2 model used the cell line as the block; name the column the user confirms); `case_peaks` and `control_peaks` are
peak group names (default: the side's `peak_group` values); `pooled` (true/false) marks a pooled comparison (left out of the common
motifs). `peak_files.csv`: `name,path`, existing peak files usable as peak groups. `diff_tables.csv`: `name,regions,path`, existing
differential tables (`peaks` or `promoters`) that are not recomputed. `motif_targets.csv`: `name,type,target,comparison,label,min_peaks`,
with `type` gene (a gene symbol) or regions (a BED in the pipeline genome's coordinates). Each file is named in config.yaml
(`comparisons:`, `peak_files:`, `diff_tables:`, `motif_targets:`). The README section "Downstream analyses" has the full rules and
the outputs.

### Input paths on a Mac

- Write paths in full (`/Volumes/SeqDrive/data/x.fastq.gz`, `/Users/you/data/x.fastq.gz`), with `~/` (`~/data/x.fastq.gz`),
  or relative to this folder (`original_data/fastq/x.fastq.gz`).
- A file on a drive is read in place. The top-level folder holding it (`/Users`, `/Volumes/<name>`, or e.g. `/data`) is
  mounted **read-only** inside the analysis at the same path. Nothing is copied from it. The drive must be connected when the
  run starts, or the launcher stops before anything runs.
- Docker Desktop shares only `/Users`, `/Volumes`, `/private`, `/tmp` and `/var/folders` by default. For a folder elsewhere,
  add it in Docker Desktop → Settings → Resources → File sharing (the launcher stops with that message until you do; or move
  the file under `/Users` or `/Volumes`).
- **Network paths (`smb://...`, `cifs://`, `afp://`, `nfs://`, `//server/share/...`) are refused.** Mount the share in Finder (it
  then appears under `/Volumes/<name>`) and write the `/Volumes/<name>/...` path.
- No path may contain a comma (it breaks the container's mount).
- The output folders `outdir`, `metadata_dir` and `intermediate_dir` must be relative (`./results`, `./metadata`,
  `./intermediate_files`); an absolute path there is refused.
- Only `config.yaml` and the CSV files in the project folder itself are checked and mounted. Keep the working CSVs there (the
  samplesheet must be there), and use `examples/` for templates.
- Reference files on this Mac are in `~/REFERENCES`. This is an **example layout**, not a requirement; ask the user for their
  own files:

```yaml
genome_index: ~/REFERENCES/bowtie2/t2t/chm13v2.0                 # bowtie2 index PREFIX (T2T-CHM13)
chrom_sizes: ~/REFERENCES/chr_size/t2t.chrom.sizes               # recorded only
blacklist: ~/REFERENCES/blacklist/t2t.blacklist.bed              # empty or null = skip BLACKLIST_FILTER
tss_bed: ~/REFERENCES/genomes/t2t/t2t.curated.norandom.tss.bed  # required when TSS enrichment runs
effective_genome_size: 3100000000                                 # MACS3 -g (T2T-CHM13)
```

(The index and file names are examples: confirm them with the user; the launcher warns when a file is missing or the index has
no `.bt2` files.)

## Key config choices (config.yaml; every key has a default)

The full list with every default is in the pipeline's `nextflow.config`; the example is `examples/config.yaml`. The keys a
project usually sets:

- `project_name`, `samplesheet`, `peak_merges`.

  `tss_bed` (required when TSS enrichment runs and a library has a `tmm_group`), `effective_genome_size` (required when MACS3 runs
  and a library has a `peak_group`), `contamination_index` (null = skip CONTAMINATION).

  `diff_tables`, `motif_targets` (null by default); `species`, `genome_build` (`hs1`), `bsgenome`, `org_db`; the `diff_*`,
  `annotation_*` and `motif_*` values (defaults are the AV values; the README table has each one with its older AV or AM value);
  `plot_font` (Helvetica), `plot_format` (svg).
- **Trimming**: `trim_adapter_set: 'NexteraPE-PE'`, `trim_illuminaclip: '2:30:10:8:True'`, `trim_steps`, `trim_minlen: 25`.
- **Alignment**: `bowtie2_mode: local`, `bowtie2_minins: 10`, `bowtie2_maxins: 2000`, `bowtie2_args` (empty), `align_chunk_pairs:
  10000000` (the output is the same with `0`), `alignment_min_pct: 20` (warning only).
- **Filtering**: `mapq: 30`, `remove_chroms: chrM`.
- **TMM**: `tmm_bin_size: 10000`, `tmm_max_frag: auto`, `tmm_group_column: tmm_group`.
- **bigWig**: `bigwig_bin_size: 10`, `bigwig_units: none`, `bigwig_extend_reads: true`, `bigwig_center_reads: false`, `bigwig_args`.
- **MACS3**: `macs3_qvalue: 0.05`, `macs3_min_length: 250`, `macs3_max_gap: 500`, `macs3_fe_cutoff: 2.0` (a value of 1 or lower
  turns it off), `macs3_call_summits: false`, `macs3_broad: false`, `macs3_broad_cutoff: 0.1`, `macs3_args`.
- **QC**: `tss_flank: 2000`.
- **Outputs and bookkeeping**: `outdir`, `metadata_dir`, `intermediate_dir`, `publish_intermediates: false`, `publish_mode: auto`,
  `keep_work: true`, `work_volume: true`.
- **This Mac**: `max_cpus`, `max_memory_gb` (lower the run's budget; default: at most 75% of the memory, leaving 3 GB to the

- Leave `fastq_dir` as `null`.

Changing a threshold, `bowtie2_minins` or `bowtie2_maxins`, `remove_duplicates`, `tn5_shift` or a MACS3 setting is a scientific
decision: tell the user and get confirmation first.

## Monitoring a run

```bash
bash utils/run_atacseq.sh status        # the state, the failed step if any, the last log lines, the work volume's name and size
```

Look at `metadata/nf_logs/last_run.status` and the newest `metadata/nf_logs/nextflow_<timestamp>.log`. The per-step trace is
`metadata/pipeline_info/execution_trace_<timestamp>.txt` (the newest one). A run ends with `Pipeline completed successfully` or
`Pipeline FAILED` in the log. Poll every few minutes; alignment of a full project takes hours.

## When a run fails

1. Read `metadata/nf_logs/last_run.status` and the end of the newest `metadata/nf_logs/nextflow_<timestamp>.log`. It names the
   failed step and its exit status. For a startup error there is no failed step: the message says what to fix.
2. In `metadata/failed_tasks/<timestamp>/<step>/` read `.command.sh` (what ran), `.command.err` and `.command.log` (what it said),
   and `.exitcode`. For a step that *succeeded*, the same command is saved in `results/<...>/log/<name>_command.sh`.
3. Common cases:
   - **Exit status 3** is a known data problem; it is not retried and the message says what to fix. Typical: a bowtie2 index that
     is not there (ALIGN, CONTAMINATION); an empty or missing BAM; unequal or truncated FASTQ pairs (COUNT_PAIRS); a chunk log that
     cannot be merged (ALIGN_MERGE); orphan reads after blacklist filtering (BAM_FINALIZE); no contig left after `remove_chroms`; a
     scale-factor multiplier missing or NaN (BIGWIG); a MACS3 target BAM missing or empty; a file listed in a peak merge missing; a
     TMM group with fewer than 2 libraries or no proper pairs (NORM_TMM).
   - **Exit status 137, 140 or 143** (out of memory or killed): retried automatically with more memory, up to the budget. If a step
     still fails, check the budget in the run banner and the step's `peak_rss` in the trace. Raising the budget is the user's decision
     (`max_memory_gb`, or a bigger Docker Desktop memory setting): ask first.
   - **A library of a TMM or peak group has no final BAM** (its group member failed or was excluded): the run fails on purpose. Fix
     the samplesheet; do not remove the sample from the code.
   - **Disk full**: the run stops and can be resumed after space is made (see the disk check in `run`); `clean` (ask first) deletes
     the work volume.
   - **Join mismatch messages at the end of the Nextflow log** are usually a side effect of an earlier abort: read the first ERROR.
4. Fix the input or config, then re-run `bash utils/run_atacseq.sh run --detach`. Completed steps are reused.
5. If the failure looks like a bug in the shared pipeline rather than in this project's data or config, **tell the user and stop**.
   Do not patch `{{PIPELINE_DIR}}`.

## Customizing this project's analysis

Every step runs one script from `{{PIPELINE_DIR}}/bin/`. To change a step for this project only, copy that script into `utils/`,
edit the copy, and add a `config.yaml` line **named after the script** (file name without extension) with the copy's path. The
shared script stays untouched for everyone else.

```bash
cp "{{PIPELINE_DIR}}/bin/qc_frip.sh" utils/                          # 1. copy
# 2. edit utils/qc_frip.sh (keep Unix line endings: LF; keep the header's CLI and output contract)
# 3. add to config.yaml:   qc_frip: utils/qc_frip.sh
bash utils/run_atacseq.sh run --detach                              # 4. only that step (and what depends on it) re-runs
```

Write override paths with forward slashes (`utils/...`): they are read inside the Linux container. Keep `.R`, `.py` and `.sh`
overrides with Unix (LF) line endings: the project's `.gitattributes` (made by `init`) keeps `utils/` in LF.

To keep a default script but pass it extra arguments, add `<script name>_args: "..."`. Each script's header lists the arguments the
pipeline passes and the files it must write; keep both compatible. `.py` runs with `python3`, `.R` with `Rscript`, anything else with
`bash`, all inside the container.

| Script (= `config.yaml` key) | What it controls |
|---|---|
| `fastqc.sh` | FastQC on raw and trimmed reads (`fastqc_args`) |
| `trim.sh` | Trimmomatic paired-end trimming (`trim_*` keys) |
| `count_pairs.sh` | COUNT_PAIRS: read pairs per library, which sets the number of ALIGN chunks (`align_chunk_pairs`) |
| `align.sh` | ALIGN: bowtie2 alignment of one chunk (`bowtie2_*` keys; `bowtie2_args`, then `align_args`) |
| `align_merge.sh` | ALIGN_MERGE: chunk BAMs joined in chunk order, chunk logs summed (`align_merge_args`) |
| `merge_bowtie2_logs.py` | Helper of ALIGN_MERGE that sums the bowtie2 logs; the key `merge_bowtie2_logs` replaces it |
| `alignment_summary.py` | bowtie2 rates per sample and the warning threshold (`alignment_min_pct`) |
| `bam_filter.sh` | MAPQ and flag filter, `remove_chroms`, raw stats |
| `dedup.sh` | sambamba markdup (`remove_duplicates`) |
| `blacklist_filter.sh` | pair-aware blacklist removal |
| `bam_finalize.sh` | final sort, index, stats, orphan check |
| `tn5_shift.sh` | alignmentSieve --ATACshift (`tn5_shift: true`) |
| `qc_chrom_fraction.py` | chrM and other contig fractions |
| `contamination.sh` | unmapped-read screen against the contaminant index |
| `qc_fragment_sizes_table.R`, `qc_fragment_sizes_plot.R` | fragment-size tables and plots |
| `norm_tmm.R` | TMM scale factors per group (statistician's script; its arithmetic is not for local changes) |
| `bigwig.sh` | bamCoverage tracks (`bigwig_*` keys; `bigwig_args`) |
| `qc_tss_enrichment.sh`, `qc_tss_table.py` | TSS enrichment per bigWig and the table |
| `callpeaks_macs3.sh` | MACS3 per peak group (`macs3_*` keys; `macs3_args`) |
| `peak_merge.sh` | bedops merge of peak groups |
| `qc_peak_stats.py` | peak counts and widths |
| `qc_frip.sh`, `qc_frip_table.py` | FRiP per sample against its own peak group |
| `multiqc.sh` | MultiQC report (`multiqc_args`) |
| `my_theme.R` | plot theme (the R plots use it; `my_theme_py.py` is not used by any step) |

- **Plot-only changes** (colours, labels, sizes): replace the **plot** script (`qc_fragment_sizes_plot.R`) and/or `my_theme.R`.
  Plot steps read only the tables.
- **Changing what is computed:** replace the matching table or compute script; keep its output names, or also replace the plot
  script.
- Anything that changes normalisation factors, thresholds, groups or models is a scientific decision: tell the user and get
  confirmation first.
- A plot tweak is quick when `keep_work` is `true` (the default) and the work folder has not been cleaned: only the plot steps
  re-run. After `clean`, or with `keep_work: false`, the affected part of the pipeline is recomputed.

## Analyses beyond the pipeline (extra steps)

Analyses the pipeline doesn't do (a different statistical test, a custom plot, a comparison across samples, ...) are allowed. The
project's own scripts run through the launcher's `script` command; the pipeline's own steps still run only with `run`.

**Convention**
- The script lives in `utils/<name>.<R|py|sh>` (`utils/` already holds this project's script replacements and extra steps).
- Its outputs go to `results/<name>/`: a **new** subfolder of `results/` named after the analysis, never one of the pipeline's own
  entries (`qc`, `bam`, `scale_factors`, `bigwig`, `peaks`, `intermediate_files`; see "Results").
- Inputs are the pipeline's outputs (e.g. `results/scale_factors/`, `results/bam/final/`, `results/peaks/macs3/`) or files the user
  provides (the user says where; never move raw data). The script reads them relative to the project folder and writes only to
  `results/<name>/`.

**Workflow**
1. Ask the user for the context and the question ("Ask about the experiment" applies); record it in `CONTEXT.md`.
2. `statistician` designs the analysis for anything statistical: method, assumptions, what the result can and cannot say.
3. `code-supervisor` (via `implementer`) writes `utils/<name>.*`.
4. The lead runs it: `bash utils/run_atacseq.sh script utils/<name>.R [args...]`. The script must be inside the project folder;
   the interpreter follows the extension (`.R` Rscript, `.py` python3, `.sh` bash); the working directory is the project folder.
   It runs in the foreground, in the pipeline's image, with the same CPU and memory budget as `run`. Arguments cannot contain
   double quotes.
5. `log-inspector` reads `metadata/script_logs/<name>_<YYYYMMDD_HHMMSS>.log`: a header (date, project, script, md5, arguments,
   image and image ID, budget, working directory), the output, and a footer `-- exit code N --`. The launcher's exit code is the
   script's.
6. `results-reporter` and/or `figure-maker` (PNG) review the output.
7. `methods-writer` writes `results/<name>/METHODS.md`: the method, the tool and package versions (from the log header and the
   script) and the parameters.

Commit the script (`utils/` is tracked) after asking the user.

**Tier 1 (default): run it through `script`.** That uses the pipeline's image and its memory limits, and gives a log. The image
holds the tools the pipeline runs (bowtie2, samtools, sambamba, bedtools, deepTools, MACS3, Trimmomatic, FastQC, MultiQC) and the R
and Python packages the pipeline's own scripts use (for example edgeR and csaw for TMM). It is not known from this folder which
other packages the image holds: check with a short test script before relying on one. Installing R or Python packages at run time
is **not** allowed (not reproducible).

**Tier 2 (fallback): run on the host.** Only when the image lacks the needed tool or package. Ask the user explicitly; if they agree,
run it on the Mac with the versions recorded (R `sessionInfo()`, `pip freeze`) in `results/<name>/` and `CONTEXT.md`, and say
in the Methods that it ran outside the pinned image.

Never install software system-wide, and never edit the pipeline folder, without asking. The pipeline's own steps are still only run
with `run`.

## Legacy behaviour toggles

The pipeline fixes several legacy bugs by default. These config values reproduce the legacy behaviour.

| Key | Default here | Legacy value | What it does |
|---|---|---|---|
| `mapq` | 30 | `0` | MAPQ filter. Legacy wrote the literal word `mapq` into samtools, which reads it as 0. |
| `remove_chroms` | `chrM` | `''` | chrM removal. Legacy kept chrM. |
| `tmm_group_column` | `tmm_group` | `tmm_group_legacy` | Exact groups vs the legacy file-name membership (K27M with K27MKO, x42c with HGGx42c in AV). |
| `tmm_max_frag` | `auto` | `1999` | Maximum fragment size for TMM. Legacy kept the first sample's maximum (1999 in AV). |
| `tn5_shift` | `false` | `false` | `true` is a new option (alignmentSieve --ATACshift), not legacy. |
| `macs3_fe_cutoff` | `2.0` | `1.0` (AM) or `4.0` (the AV merge used the fe4.0 files) | MACS3 `--fe-cutoff`; a value of 1 or lower turns it off. |
| `macs3_call_summits` | `false` | `true` (AM) | Writes `<prefix>_summits.bed`. |
| `macs3_min_length`, `macs3_max_gap` | `250`, `500` | `null` (AM) | MACS3 `--min-length`, `--max-gap`; null leaves the option out. |
| `remove_duplicates` | `true` | `true` | `false` marks duplicates but keeps them. |
| `peak_merges` | `peak_merges.csv` (AV) | `null` (AM) | AM's merge_peaks.sh is not a merge. |
| `bowtie2_minins` | `10` | `null` | bowtie2 `-I`. Legacy passed no `-I`. |
| `bowtie2_args` | `''` | `'-N 1 -t'` | Extra bowtie2 arguments. Legacy `-N 1` and `-t`. |
| `align_chunk_pairs` | `10000000` | `0` | Read pairs per ALIGN task. `0` = one ALIGN task per library. Not a legacy behaviour; the output is the same. |
| `diff_pe` | `both` | `none` (older AV and AM) | csaw `pe`: paired data counted as paired (`none` = counted as single-end, the older csaw_parameters.R). |
| `diff_lfc` | `0.585` | `1` (older AV and AM) | Absolute logFC threshold of the differential tables and BEDs. |
| `diff_table` | `best` | `combined` (AM) | Which overlapResults table gives the statistics. |
| `diff_dedup` | `null` (= `false` when `remove_duplicates` is on) | `auto` (the legacy rule: TRUE for comparisons with at most two BAMs) | csaw duplicate handling per comparison. |
| `annotation_fdr` | `null` | `0.1` (older AV) | `null` annotates all regions; a number keeps the regions below that FDR. |
| `motif_regions` | `promoters` | `promoter_sites,non-promoter_sites,all_sites` (AM) | Region sets of the motif analysis: the promoter differential table (AV26) or the annotation subsets (older). |
| `motif_lfc` | `0.585` | `1` (older AV and AM) | Bins for the motif analysis: logFC above this in absolute value. |
| `plot_format` | `svg` | `pdf` (legacy files) | Downstream plots: svg in `plot_font` (Helvetica), or the legacy pdf. |

A `# TOGGLE` line in the AM example is not read; to use one, copy it over the key line below it.
