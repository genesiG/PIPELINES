# AGENTS.md — ATAC-seq project (Rephill Lab)

This directory is **one lab member's ATAC-seq project**, run with the lab's shared Nextflow pipeline at
`/project/rephilllab/ATACSEQ`. You are here to help this user run the pipeline on *their* data, check results, and customize
*their* analysis. You are not here to change the pipeline itself.

## Hard rules

1. **Never edit anything under `/project/rephilllab/`** (`ATACSEQ/`, `bin/`, `nf_containers/`) unless the user explicitly asks
   to change the **lab-wide** pipeline. Every lab member runs those files. To change how this project's analysis or plots work,
   use a per-project override (see "Customizing"), never an edit to the shared copy.
2. **Only launch the pipeline with `run_atacseq.sh`.** Do not call `nextflow`, `bowtie2`, `samtools`, `Rscript` or `python`
   analysis scripts yourself, and do not `bsub` your own jobs. `run_atacseq.sh` handles LSF submission, containers, logging and
   `-resume`.
3. **Do not run anything compute- or memory-heavy in the terminal.** The login node caps memory at about 2 GB. Reading logs,
   CSVs and small files is fine; opening a BAM with anything heavier than `samtools view -H`, or running an analysis script, is not.
4. **Raw FASTQs are the only copy.** If `fastq_dir` is set in `config.yaml`, the first run *moves* (not copies) that directory's
   FASTQs into `original_data/fastq/` and rewrites `fastq_dir`; do not change it back. Otherwise the FASTQ paths in
   `samplesheet.csv` are used exactly as given and nothing is moved. Never delete, move or overwrite raw data.
5. **Ask before destructive or expensive actions:** deleting `results/`, `intermediate_files/`, `metadata/`, `.nextflow/`, or the
   Nextflow work directory (`/project/rephilllab/nf_work/$USER/<this directory's name>/`), or launching a run when nothing has
   changed. A full run aligns every library and is expensive.
6. **Do not hand-edit files in `results/` or `intermediate_files/`.** They are regenerated by the pipeline; change the inputs or
   an override instead.
7. **Do not guess data paths.** FASTQ, bowtie2 index, blacklist, GTF, TSS and chrom.sizes paths come from the user. Ask.

## Layout

```
config.yaml                    the run's settings: the file you usually edit (keys: README.md, "config.yaml keys")
samplesheet.csv                one row per library (schema below)
peak_merges.csv                optional: one row per merged peak set (schema below)
utils/                         this project's replacements for pipeline scripts (see "Customizing"); created by init, empty until used
original_data/fastq/           FASTQs, only if fastq_dir mode is used
intermediate_files/            trimmed FASTQ, aligned, filtered and tn5-shifted BAMs
results/                       all outputs (see "Results")
metadata/nf_logs/              LSF logs of each run's head job (read these first)
metadata/.nextflow.log         Nextflow's detailed log (the run's first ERROR is the cause)
metadata/pipeline_info/        execution_trace_<timestamp>.txt, execution_report_, execution_timeline_, pipeline_dag_<timestamp>.html (one set per launch, yyyyMMdd_HHmmss)
.nextflow/                     Nextflow's resume cache: leave alone
examples/                      starter CSVs, the config.yaml template, and examples/projects/{av_atacseq_2026,am_atacseq}
```

This directory is a git repository tracking `config.yaml`, the input CSVs, `examples/` and any override scripts. Data, results and
logs are gitignored. Committing after a meaningful config change is a good habit, but ask the user first.

## How to run

```bash
run_atacseq.sh init        # once, in a new empty project directory: scaffolds files, git init, never runs anything
# edit config.yaml and samplesheet.csv (and peak_merges.csv if used)
run_atacseq.sh             # from this directory; reads ./config.yaml (or: run_atacseq.sh other.yaml)
```

It is safe to run from the login node: it stages `fastq_dir` if set, makes sure the Nextflow launcher exists, and submits one LSF
head job (queue rhel9, 8 GB, 72 h) and returns. The head job runs every step as its own LSF job, each in a container. Startup
validation of `config.yaml` and the CSVs happens first and fails with a clear message before any job is submitted.

Re-running is always `run_atacseq.sh` again. `-resume` is built in, so any step whose inputs, script and settings have not changed
is reused from cache. There is no "run just step X" command: change the thing, re-run, and caching does the rest.

If `run_atacseq.sh` is not found, the user's `PATH` is missing `/project/rephilllab/bin`, or the symlink has not been created yet.
Tell them; do not edit their `~/.bashrc` without asking.

## Input files

### samplesheet.csv: one row per library

```
sample_id,fastq_1,fastq_2,condition,replicate,tmm_group,tmm_group_legacy,peak_group,exclude
```

| Column | Meaning |
|---|---|
| `sample_id` | Unique library name, used verbatim in file names; must match `^[A-Za-z0-9][A-Za-z0-9_.-]*$`. |
| `fastq_1`, `fastq_2` | Absolute paths of the R1 and R2 FASTQ (paired-end only). Both are required. |
| `condition`, `replicate` | Labels for the QC tables only (not used by any normalisation). Blank is allowed. |
| `tmm_group` | TMM normalisation group (exact name, used by `tmm_group_column: tmm_group`). Blank = the sample is not normalised: no bigWig, no TSS enrichment. A group needs at least 2 active samples. |
| `tmm_group_legacy` | Second group column, used when `tmm_group_column: tmm_group_legacy` (reproduces the legacy file-name membership). |
| `peak_group` | MACS3 peak group (replicates are pooled, no control). Blank = the sample is in no peak calling and gets no FRiP. A `peak_merges.csv` row can name peak groups. |
| `exclude` | empty/`false`/`0`/`no` keep the row; `true`/`1`/`yes` drop it from the whole run (anything else is a startup error). |
| `bam` | Optional. A final BAM of the library instead of FASTQ (the file ends in `.bam`; `fastq_1` and `fastq_2` must be empty). The BAM is assumed filtered, duplicate-removed and blacklist-filtered. |

Rules enforced at startup (the run stops with a message): no unknown column (the allowed names are the table above); required
columns present; unique `sample_id`; every FASTQ exists; `fastq_1` and `fastq_2` are different files; no two FASTQs share a file
name; group values match the id pattern; a TMM group has at least 2 active samples; `tmm_group_column` names a column of the sheet.
Rows with `exclude: true` are kept in the file for the record. A group that only has excluded members is not in the run.

### peak_merges.csv: one row per merged peak set (optional)

```
name,peak_groups
high_merged,"BT54_high,BT88_high"
```

`name` is the output name (`results/peaks/merged/<name>.merged.bed`). `peak_groups` is a quoted comma list of `peak_group`
values; each must have an active sample. Set `peak_merges: peak_merges.csv` in config.yaml (or `null`).

### Downstream CSVs (optional; used only when run_differential, run_annotation or run_motifs is on)

`comparisons.csv`: `name,case,control,group_column,block_column,case_peaks,control_peaks,pooled,fixed_dispersion`. `case` and
`control` are quoted comma lists of values of `group_column` (default `condition`); `block_column` is an optional covariate column
(for example `tmm_group` for the legacy gd2 cell lines); `case_peaks` and `control_peaks` are peak group names (default: the side's
`peak_group` values); `pooled` (true/false) marks a pooled comparison (left out of the common motifs). `peak_files.csv`: `name,path`,
existing peak files usable as peak groups. `diff_tables.csv`: `name,regions,path`, existing differential tables (`peaks` or
`promoters`) that are not recomputed. `motif_targets.csv`: `name,type,target,comparison,label,min_peaks`, with `type` gene (a gene
symbol) or regions (a BED in the pipeline genome's coordinates). Each file is named in config.yaml (`comparisons:`, `peak_files:`,
`diff_tables:`, `motif_targets:`). The README section "Downstream analyses" has the full rules and the outputs.

### config.yaml keys

The flat `key: value` file. Every key has a default in the pipeline's `nextflow.config` (see the README table for every key and
its default). The reference keys with no default are: `genome_index` (bowtie2 index prefix, required), `effective_genome_size`
(required when some sample has a peak_group), `tss_bed` (required when some sample has a tmm_group), `blacklist` (empty = skip),
`contamination_index` (empty = skip), `chrom_sizes` and `gtf` (recorded and checked only). `lsf_watchdog: false` turns the
watchdog off.

## Monitoring a run

```bash
bjobs -u $USER                                          # the head job is atacseq_<project_name>_<timestamp>
tail -n 50 metadata/nf_logs/nextflow_<timestamp>.out    # latest = ls -t metadata/nf_logs/*.out | head -1
head -n 1 metadata/pipeline_info/execution_trace_<timestamp>.txt    # newest = this launch; the trace has a header line; read the column numbers from it
```

A run ends with `Pipeline completed successfully` or `Pipeline FAILED` in the `.out` log. Poll every few minutes; alignment of a
full project takes hours.

## When a run fails

1. Read the end of the newest `metadata/nf_logs/nextflow_<timestamp>.out`. It names the failed step, its exit status, the command,
   and its `Work dir:`. For a startup error there is no work dir: the message says what to fix.
2. In that work dir read `.command.sh` (what ran), `.command.err` and `.command.log`. For a step that *succeeded*, the same command
   is saved permanently as `results/.../log/<name>_command.sh` (for example `results/qc/bowtie2/log/<sample>_align_command.sh`; with chunked alignment, `<sample>.chunkNNN_align_command.sh` for each chunk and `<sample>_align_merge_command.sh` for the merge).
3. Common cases:
   - **Exit status 3** is a known data problem; it is not retried and the message says what to fix. Typical: a bowtie2 index that
     is not there (ALIGN, CONTAMINATION); an empty or missing BAM; unequal or truncated FASTQ pairs (COUNT_PAIRS); a chunk log that cannot be merged (ALIGN_MERGE); orphan reads after blacklist filtering (BAM_FINALIZE); no contig
     left after `remove_chroms`; a scale-factor multiplier missing or NaN (BIGWIG); a MACS3 target BAM missing or empty; a file
     listed in a peak merge missing; a TMM group with fewer than 2 libraries or no proper pairs (NORM_TMM).
   - **Exit status 137, 140, 143** (out of memory or wall time): retried automatically with more memory. If a step still fails,
     report it to the user.
   - **A sample of a TMM or peak group has no final BAM** (its group member failed or was excluded): the run fails on purpose.
     Fix the samplesheet, do not remove the sample from the code.
   - **Run hangs with a task SUBMITTED but no LSF job** (`bjobs -u $USER` shows nothing for it, its work dir has no
     `.command.begin`): the LSF job was aborted at dispatch. The head job's watchdog prints an `ATACSEQ WATCHDOG:` block and stops
     the run. Read the block, then relaunch with `run_atacseq.sh` (finished steps are reused). If it happens again, report it.
   - **Join mismatch messages at the end of `.nextflow.log`** are usually a side effect of an earlier abort: read the first ERROR.
4. Fix the input or config, then re-run `run_atacseq.sh`. Completed steps are reused.
5. If the failure looks like a bug in the shared pipeline rather than in this project's data or config, **tell the user and stop**.
   Do not patch `/project/rephilllab/ATACSEQ`.

## Customizing this project's analysis

Every step runs one script from `/project/rephilllab/ATACSEQ/bin/`. To change a step for this project only, copy the script into
`utils/`, edit the copy, and add a `config.yaml` line **named after the script** (file name without extension) with the copy's path:

```bash
cp /project/rephilllab/ATACSEQ/bin/qc_frip.sh utils/       # 1. copy
# 2. edit utils/qc_frip.sh (keep its header's CLI and output contract)
# 3. add to config.yaml:   qc_frip: utils/qc_frip.sh
run_atacseq.sh                                              # 4. only that step (and what depends on it) re-runs
```

Add `<script name>_args: "..."` to pass extra arguments to a shipped script. Each script's header lists the arguments the pipeline
passes and the files it must write; keep both compatible. `.py` runs with `python3`, `.R` with `Rscript`, anything else with `bash`.

| Script (= `config.yaml` key) | What it controls |
|---|---|
| `fastqc.sh` | FastQC on raw and trimmed reads (`fastqc_args`) |
| `trim.sh` | Trimmomatic paired-end trimming (`trim_*` keys; extra Trimmomatic arguments through `trim_args`) |
| `count_pairs.sh` | COUNT_PAIRS: read pairs per library, which sets the number of ALIGN chunks (`align_chunk_pairs`; `count_pairs_args`) |
| `align.sh` | ALIGN: bowtie2 alignment of one chunk (`bowtie2_*` keys; extra bowtie2 arguments through `bowtie2_args`, then `align_args`) |
| `align_merge.sh` | ALIGN_MERGE: chunk BAMs joined in chunk order, chunk logs summed (`align_merge_args`) |
| `merge_bowtie2_logs.py` | Helper of ALIGN_MERGE that sums the bowtie2 logs; the key `merge_bowtie2_logs` replaces it |
| `alignment_summary.py` | bowtie2 rates per sample and the warning threshold |
| `bam_filter.sh` | MAPQ and flag filter, `remove_chroms`, raw stats |
| `dedup.sh` | sambamba markdup (`remove_duplicates`) |
| `blacklist_filter.sh` | pair-aware blacklist removal |
| `bam_finalize.sh` | final sort, index, stats, orphan check |
| `bam_prealigned.sh` | a final BAM from the samplesheet `bam` column: copy (or sort), index, flagstat, idxstats (`bam_prealigned_args`) |
| `tn5_shift.sh` | alignmentSieve --ATACshift (`tn5_shift: true`) |
| `qc_chrom_fraction.py` | chrM and other contig fractions |
| `contamination.sh` | unmapped-read screen against the contaminant index |
| `qc_fragment_sizes_table.R`, `qc_fragment_sizes_plot.R` | fragment-size tables and plots |
| `norm_tmm.R` | TMM scale factors per group (statistician's script; its arithmetic is not for local changes) |
| `bigwig.sh` | bamCoverage tracks (`bigwig_*` keys; `bigwig_args`) |
| `qc_tss_enrichment.sh`, `qc_tss_table.py` | TSS enrichment per bigWig and the table |
| `callpeaks_macs3.sh` | MACS3 per peak group (`macs3_*` keys; `macs3_args` and `callpeaks_macs3_args`) |
| `peak_merge.sh` | bedops merge of peak groups |
| `qc_peak_stats.py` | peak counts and widths |
| `qc_frip.sh`, `qc_frip_table.py` | FRiP per sample against its own peak group |
| `multiqc.sh` | MultiQC report (`multiqc_args`) |
| `txdb_build.R` | TxDb from the GTF, for the promoter table and the annotation (`txdb_build_args`) |
| `diff_accessibility.R` | csaw and edgeR differential accessibility for one comparison (`run_differential`; `diff_*` keys; `diff_accessibility_args`) |
| `diff_annotate.R` | ChIPseeker annotation of one differential table (`run_annotation`; `annotation_*` keys; `diff_annotate_args`) |
| `motif_enrichment.R` | monaLisa motif enrichment, per comparison and region set, or per motif target (`run_motifs`; `motif_*` keys; `motif_enrichment_args`) |
| `motif_common.R` | motifs significant in several comparisons, per region set (`motif_common_*` keys; `motif_common_args`) |
| `my_theme.R`, `my_theme_py.py` | plot theme (R plots use `my_theme.R`; `my_theme_py.py` is not used by any step) |

- **Plot-only changes** (colours, labels, sizes): replace the **plot** script (`qc_fragment_sizes_plot.R`) and/or `my_theme.R`.
  Plot steps read only the tables.
- **Changing what is computed:** replace the matching table or compute script; keep its output names, or also replace the plot script.
- Anything that changes normalisation factors, thresholds, groups or models is a scientific decision: tell the user and get
  confirmation first.

## Legacy behaviour toggles

The pipeline fixes several legacy bugs by default. These config values reproduce the legacy behaviour.

| Key | Default here | Legacy value | What it does |
|---|---|---|---|
| `mapq` | 30 | `0` | MAPQ filter. Legacy wrote the literal word `mapq` into samtools, which reads it as 0. |
| `remove_chroms` | `chrM` | `''` | chrM removal. Legacy kept chrM. |
| `tmm_group_column` | `tmm_group` | `tmm_group_legacy` | Exact groups vs the legacy file-name membership (K27M with K27MKO, x42c with HGGx42c in AV). |
| `tmm_max_frag` | `auto` | `1999` | Maximum fragment size for TMM. Legacy kept the first sample's maximum (1999 in AV). |
| `tn5_shift` | `false` | `false` | `true` is a new option (alignmentSieve --ATACshift), not legacy. |
| `macs3_fe_cutoff` | `2.0` | `1.0` (AM) or `4.0` (the AV merge used the fe4.0 files) | MACS3 `--fe-cutoff`; a value <= 1 turns it off and drops `.fe` from the file name. |
| `macs3_call_summits` | `false` | `true` (AM) | Writes `<prefix>_summits.bed`. |
| `macs3_min_length`, `macs3_max_gap` | `250`, `500` | `null` (AM) | MACS3 `--min-length`, `--max-gap`; null leaves the option out. |
| `remove_duplicates` | `true` | `true` | `false` marks duplicates but keeps them. |
| `contamination_index` | `null` | not set (AM) | Null skips CONTAMINATION. AM's contaminant index contains mm10: leave it null for mouse. |
| `peak_merges` | `peak_merges.csv` (AV) | `null` (AM) | AM's merge_peaks.sh is not a merge. |
| `bowtie2_minins` | `10` | `null` | bowtie2 `-I`. Legacy passed no `-I`. |
| `bowtie2_args` | `''` | `'-N 1 -t'` | Extra bowtie2 arguments. Legacy `-N 1` and `-t`; the default is the CUT&RUN flags plus `-X 2000` (2026-10-28). |
| `diff_pe` | `both` | `none` (older AV and AM) | csaw `pe`: paired data counted as paired (`none` = counted as single-end, the older csaw_parameters.R). |
| `diff_lfc` | `0.585` | `1` (older AV and AM) | Absolute logFC threshold of the differential tables and BEDs. |
| `diff_table` | `best` | `combined` (AM) | Which overlapResults table gives the statistics. |
| `diff_dedup` | `null` (= `false` when `remove_duplicates` is on) | `auto` (the legacy rule: TRUE for comparisons with at most two BAMs) | csaw duplicate handling per comparison. |
| `annotation_fdr` | `null` | `0.1` (older AV) | `null` annotates all regions; a number keeps the regions below that FDR. |
| `motif_regions` | `promoters` | `promoter_sites,non-promoter_sites,all_sites` (AM) | Region sets of the motif analysis: the promoter differential table (AV26) or the annotation subsets (older). |
| `motif_lfc` | `0.585` | `1` (older AV and AM) | Bins for the motif analysis: logFC above this in absolute value. |
| `plot_format` | `svg` | `pdf` (legacy files) | Downstream plots: svg in `plot_font` (Helvetica), or the legacy pdf. |
| `align_chunk_pairs` | `10000000` | `0` | Read pairs per ALIGN task. `0` = one ALIGN task per library. Not a legacy behaviour; the output is the same. |

The AM example (`examples/projects/am_atacseq/config.yaml`) lists these legacy values as `# TOGGLE` comment lines above the key.
A `# TOGGLE` line is not read; to use one, copy it over the key line below it.

## Results

Every step's own `log/` subfolder holds a `*_command.sh`, the exact command that ran, fully filled in.

```
results/qc/fastqc/raw/, results/qc/fastqc/trimmed/        FastQC zips and html (per FASTQ)
results/qc/trimmomatic/                                    Trimmomatic logs
results/qc/bowtie2/                                        bowtie2 logs per sample (summed over chunks);
                                                     log/ also holds the COUNT_PAIRS, ALIGN and ALIGN_MERGE commands
results/qc/alignment/                                      alignment_summary.tsv (warning threshold flags)
results/qc/chrom_fraction/                                 chrom_fraction.tsv (only if remove_chroms)
results/bam/stats/                                         raw and final flagstat and idxstats, markdup log, orphan_check
results/bam/final/                                         final BAM and .bai per library (the analysis BAM when tn5_shift is off)
results/bam/tn5/                                           S.tn5.bam and .bai (only if tn5_shift)
results/qc/contamination/                                  contamination tables (only if contamination_index)
results/qc/fragment_sizes/                                 fragment_sizes.tsv, fragment_size_distribution.tsv, two SVG plots
results/scale_factors/                                     <group>.scale_factors.tsv (bigwig_multiplier, edger_norm_factor, qc_pass, note), MA plots, <group>.max_frag.txt
results/bigwig/                                            <sample>.<method>.<units>.bw (for example sample.tmm.none.bw), samples with a tmm_group
results/qc/tss_enrichment/                                 per-sample TSS files and tss_enrichment.tsv
results/peaks/macs3/                                       per group: narrowPeak (or broadPeak), _peaks.xls, optional summits and gappedPeak, .macs3.log
results/peaks/merged/                                      <name>.merged.bed (only with peak_merges)
results/qc/peaks/                                          peak_stats.tsv
results/qc/frip/                                           <sample>.macs3.frip.tsv and frip.tsv
results/qc/multiqc/                                        multiqc_report.html: start here for an overview
intermediate_files/trimmed, aligned, filtered/             large intermediates (trimmed FASTQ, aligned and filtered BAMs)
metadata/pipeline_info/                                    execution_report_<timestamp>.html, execution_trace_<timestamp>.txt, execution_timeline_<timestamp>.html, pipeline_dag_<timestamp>.html
```

When summarising results, start from `results/qc/multiqc/multiqc_report.html` and `results/bam/stats/`, and check
`results/scale_factors/*.scale_factors.tsv` (`qc_pass`, `note`) before interpreting any normalised track or peak set.
